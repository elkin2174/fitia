# HU 13 — Explicación de ejercicios

Documentación de la implementación vertical (backend y frontend) de la HU 13 del MVP FITIA (Épica 3, Feature 3.1): qué se construyó, cómo funciona, trazabilidad de pruebas y guía de prueba manual.

> **Estado:** Implementado y probado. 633 pruebas backend pasando en Docker con PostgreSQL real (28 nuevas); 99 pruebas frontend pasando en Vitest (24 nuevas). Sin llamadas a la IA en tiempo de consulta (NFR-16 / AC-13-4). Latencia < 2.0 s (NFR-05 / AC-13-4).

---

## 1. Qué hace la HU 13

Permite al estudiante (especialmente principiante) consultar una explicación técnica concisa de cómo ejecutar cada ejercicio de su rutina sin salir del flujo de entrenamiento. La explicación se abre como una hoja inferior (*bottom sheet*) sobre la pantalla actual, reflejando el identificador del ejercicio en el parámetro de búsqueda `?ejercicio=<id>`.

```text
GET /api/v1/plan/exercises/{exercise_id}/guide → 200 ExerciseGuideDetailResponse (S+P; Cache-Control: no-store; NUNCA llama a la IA)
```

- **Generación previa:** La explicación la genera la IA junto con el plan semanal (HU 5) y se almacena en la columna JSONB `steps` de `plan_exercises` (validada por la restricción de comprobación `ck_plan_exercises_steps` y reglas deterministas de 2 a 4 pasos).
- **Cero llamadas a la IA al consultar (AC-13-4):** Al consultar la rutina (`/plan/today` o `/plan/days/{date}`), la explicación ya viaja embebida en cada ejercicio (`guide: {steps, disclaimer}`). Abrir la hoja inferior en el cliente es instantáneo (0 ms de espera de red).
- **Aviso orientativo oficial (Decisión 4):** Constante inmutable definida en el servidor:
  > *"Esta guía es orientativa y no reemplaza la indicación de un profesional del deporte o de la salud. Si sientes dolor, detente."*
  No se almacena en la base de datos ni es redactada por la IA.
- **Aislamiento de identificadores (Decisión 12):** Si un usuario intenta consultar el ejercicio de otro usuario, la API responde con `404 EXERCISE_NOT_FOUND` (no 403), evitando revelar la existencia de recursos ajenos.

## 2. Arquitectura y componentes

### 2.1 Backend (`apps/api`)
- **`models.py`:** Constante `EXERCISE_DISCLAIMER`.
- **`schemas.py`:** Esquemas `ExerciseGuideOut` y `ExerciseGuideDetailResponse`.
- **`repository.py`:** Método `get_exercise_guide(user_id, week_start, exercise_id)` optimizado con un único `SELECT` filtrando por el plan activo del usuario.
- **`service.py`:** Método `get_exercise_guide(user_id, exercise_id)`.
- **`router.py`:** Endpoint `GET /api/v1/plan/exercises/{exercise_id}/guide`.

### 2.2 Frontend (`apps/web`)
- **Componente `BottomSheet.tsx` (`shared/ui`):**
  - Diálogo modal accesible (`role="dialog"`, `aria-modal="true"`, `aria-labelledby`).
  - Atrapa el foco de teclado (ciclo `Tab` / `Shift+Tab`).
  - Cierra con la tecla `Escape`, con clic en el telón de fondo y con botón de cierre (≥ 44 px).
  - Restaura automáticamente el foco en el elemento que abrió la hoja al cerrarse.
- **Componente `ExerciseGuideSheet.tsx` (`features/plan`):**
  - Muestra los pasos en una lista ordenada `<ol>` numerada.
  - Renderiza el `Banner` informativo con el aviso orientativo oficial.
- **Sincronización con URL:**
  - Se vincula mediante `useSearchParams` con el parámetro `?ejercicio=<id>` usando `{ replace: true }`.
  - Permite enlaces directos hacia explicaciones específicas y soporte del botón "Atrás" del navegador/celular.

## 4. Guía de Prueba Manual

### 4.1 Prueba vía API (curl)
1. Obtener la cookie de sesión y el ID de un ejercicio desde `/api/v1/plan/today`.
2. Consultar la guía técnica del ejercicio:
   ```bash
   curl -i -X GET http://localhost:8000/api/v1/plan/exercises/<ID_EJERCICIO>/guide \
     -H "Cookie: fitia_session=<TU_TOKEN>"
   ```
3. Comprobar que responde `200 OK` con:
   - `exercise_id` y `name`.
   - Arreglo `steps` con entre 2 y 4 cadenas claras.
   - Cadena `disclaimer`: *"Esta guía es orientativa y no reemplaza la indicación de un profesional del deporte o de la salud. Si sientes dolor, detente."*
   - Encabezado `Cache-Control: no-store`.
4. Consultar un UUID inexistente o de otro usuario:
   ```bash
   curl -i -X GET http://localhost:8000/api/v1/plan/exercises/00000000-0000-0000-0000-000000000000/guide \
     -H "Cookie: fitia_session=<TU_TOKEN>"
   ```
   Responde `404 Not Found` con código `"EXERCISE_NOT_FOUND"`.

### 4.2 Prueba visual en navegador
1. Iniciar sesión y entrar a `/hoy`.
2. Tocar una tarjeta de ejercicio:
   - Se desliza hacia arriba la hoja inferior.
   - La barra de direcciones refleja `?ejercicio=<id>`.
   - Se leen los pasos numerados y el aviso en el banner azul.
3. Presionar la tecla `Escape`:
   - La hoja se cierra inmediatamente.
   - El foco regresa al botón del ejercicio presionado.
   - La URL vuelve a `/hoy`.
4. Recargar el navegador con `/hoy?ejercicio=<id>`:
   - La rutina carga y abre de inmediato la hoja inferior correspondiente.
